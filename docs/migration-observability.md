# OTEL 마이그레이션 화면

각 모듈의 OTEL 로그를 Collector가 CP로 전달하고, CP는 기존 상세/이력 모델을 제공합니다. 마이그레이션 리소스 카드에는 경로·쓰기 접근·현재 전환 조건과 최신성을 요약합니다. 수집 출처와 원본 측정 시각을 포함한 전체 상세는 모니터링의 마이그레이션 관측 탭에 표시합니다. `/v1/workflows/{id}/telemetry`는 Prometheus의 핵심 수치와 Tempo의 최근 trace ID/서비스/작업/소요 시간을 조회합니다. 프런트엔드는 공통 Axios + TanStack Query + Zod로 CP만 호출합니다.

Collector/backend 미설정, 단절, 아직 없는 표본을 구별합니다. metric 수집 시각과 원본 관측 경과를 함께 표시합니다. 수치가 없다고 0으로 표시하지 않습니다. 작업 ID는 span correlation용이며 브라우저에 OTLP SDK나 service token을 넣지 않습니다. 실제 앱 SDK는 demo 저장소에 있습니다.

`VITE_API_BASE_URL` 또는 `/api` 프록시를 CP에 연결합니다. 운영 수집 구성은 IaC `docs/migration-observability.md`를 따릅니다. 검사: `vp run check`, `vp run build`.

## 상세 화면 배치

상단은 앱·현재 단계·명령을 한 줄에 배치하고, 전체 단계는 그 아래 가로로 표시합니다. 좁은 화면에서는 줄을 바꿉니다. 작업 ID·시작 시각·실행자는 작업 정보 버튼에 마우스를 올리거나 키보드로 포커스하면 확인할 수 있습니다. 승인 대기 안내와 중단 원인은 본문에 유지합니다.

## 전환 구성도

데스크톱에서는 현재 단계·LB 비율·준비 상태를 구성도 왼쪽의 정보 패널에 배치합니다. 제목·상시 설명 문장·중복 모듈 소제목·하단 범례/출처 문구는 화면에서 제거하고 실제 상태·수치·노드 이름을 유지합니다. 출처는 별도 라이선스와 아이콘 명세에 보관합니다. 오른쪽 그림은 화면 높이와 원래 종횡비에 맞춰 축소하며, 전환 중 추가된 세부 노드까지 포함합니다. 1100px보다 좁은 화면에서는 정보를 위에 배치하고 그림 영역 안에서 가로 스크롤을 허용합니다.

stack-diagram의 공식 로고 타일·클라우드 그룹·직각 연결선 배치를 적용합니다. 로고는 data URI로 포함하며 출처는 docs/stack-diagram-icons.json에 기록합니다. 원본·대상 경로와 트래픽 가중치는 API 응답으로 표시합니다. 복제 방향은 replication의 실행 상태가 보고된 경우에만 표시합니다. 응답이 없는 경로·가중치는 미확인으로 표시합니다. 외부 이미지 요청은 발생하지 않습니다.

## 동적 전환 표시

사용자와 LB는 중앙 위, 양쪽 앱과 저장소는 같은 높이의 세로 행으로 배치합니다. 저장소 사이 선은 복제 경로이며, 서비스 사용 위치와 별도로 표시합니다. 복사량은 검증된 completed/total만 백분율로 표시하고, Redis 처리량과 backlog로 임의의 완료율을 만들지 않습니다. 객체 초기 복사는 관측 시각이 있을 때만 사용합니다.

replication 방향별 실행 상태 또는 레거시 SYNCING lifecycle과 관측값으로 복제 흐름을 표시합니다. READY만으로 서비스 경로를 대상에 넘기지 않습니다. 오래된 관측·수집 실패·리소스 오류·승인 대기·정지·완료 상태에서는 움직임을 멈춥니다. 상세 조회 실패 시 보관된 화면의 움직임도 멈춥니다. 대상 준비는 실제 INFRA/COMPUTE 보고와 리소스 준비 확인을 사용하며, 미제공 작업을 완료로 만들지 않습니다.

LB 확인 비율과 요청 비율을 구분합니다. 확인된 설정에 따라 분할 막대와 경로 굵기·흐름 밀도를 바꾸며, 흐름 표시는 실제 요청 표본 수가 아닙니다. 화살촉 크기는 선 굵기와 독립적입니다. prefers-reduced-motion에서는 움직임 없이 상태·비율·선으로 정보를 제공합니다.

## 전환 중 모듈 내부 노드

전체 구성도와 기존 사용자·LB·클라우드·앱·저장소 노드는 항상 유지합니다. 현재 RUNNING인 OBJECT_CUTOVER, REDIS_CUTOVER, DATABASE_CUTOVER 동안 해당 저장소 사이에만 라우터/프록시와 복제 노드를 추가합니다. 아래 저장소 행과 클라우드 테두리를 함께 늘려 겹침을 피합니다. 모듈이 바뀌면 이전 세부 노드는 사라지고 새 모듈의 세부 노드가 나타납니다. 완료·승인 대기·엔진 정지 시에는 기본 구성으로 돌아갑니다. 팝업·추가 하단 패널·전체 구성도 교체는 사용하지 않습니다.

CP의 현재 step 보고는 왼쪽 단계 설명에서 번역합니다. 복제 노드는 관측된 복제 상태와 수량을 사용하며, 내부 작업별 시작/완료 이벤트를 추정하지 않습니다. 노드와 제어선은 구조 설명이며 실제 개별 요청 표본이 아닙니다. 조회 실패·오래된 관측 시에는 복제 움직임을 멈춥니다. MIXED만으로 객체 저장소의 쓰기 대상이나 읽기 우선순위를 확정하지 않습니다.

프록시 노드는 앱 요청 전달 역할과 보고된 현재 목적지를 표시합니다. Redis 전환 시 왼쪽 정보 패널에서 역할 설명·보고된 쓰기 허용/정지·진행 중인 쓰기 수를 확인합니다. 목적지는 SOURCE/TARGET 관측에서만 정하고 MIXED/관측 실패 시 미확인으로 표시합니다. Proxy 관측 자체가 STALE/UNAVAILABLE인 경우에도 현재 상태를 확정하지 않습니다. Worker는 변경 데이터 복제 역할과 보고된 복제 방향·처리량을 표시합니다. 앱→프록시→저장소는 실선, 복제는 점선, 제어 지시는 회색 점선으로 구분합니다. CP의 CHECK/VERIFY 등은 왼쪽 현재 단계 설명에 표시하며 프록시 자체 작업으로 표현하지 않습니다.

확장된 저장소→복제 Worker→저장소 경로에도 데이터 조각이 이동합니다. 양방향 복제 보고 시 양쪽 방향으로 표시하며, 이 조각 수는 실제 복제 건수가 아닌 상태 시각화입니다. 관측 실패·정지·완료 시 중지하고 reduced-motion 설정에서는 숨깁니다. ACTIVE/운영 중만으로 복제 실행을 추정하지 않으며, 복제 실행 근거가 없으면 복제 노드에 ‘복제 실행 미확인’을 표시합니다.

## 변경분 스트림과 롤백 표시

옵션 `streams` 관측으로 INITIAL_COPY, CDC, KEY_EVENTS, OBJECT_CHANGES를 구분합니다. 초기 복사와 지속 변경분 반영을 별도로 표시하고, Redis 키 알림과 DB 변경 로그 노드를 복제 Worker 옆에 연결합니다. 알림 선은 변경 감지 신호이고 실제 데이터 반영은 파란 복제 경로입니다. 처리 건수·backlog·지연은 보고된 값만 표시합니다. 관측 시각과 FRESH 상태가 없는 스트림은 움직임의 근거로 사용하지 않습니다. 엔진 승인 대기와 외부 스트림 중지는 같지 않으므로 명시적으로 RUNNING인 신선한 스트림은 계속 표시합니다.

ROLLING_BACK에서는 현재 정방향 단계가 아니라 workflow.rollback.resource에 해당하는 내부 노드를 펼칩니다. 역방향은 실제 replication/streams 보고를 따라 표시하며, Proxy 원본 복귀는 route가 SOURCE일 때만 확정합니다. 확정 대기에서 개별 롤백이 허용되지 않는 현재 API 명령 정책은 바꾸지 않습니다. 트래픽 전환 중 일시 정지 후 리소스 롤백을 요청할 수 있습니다.

상세 응답의 `simulation`이 true이면 합성 수치이므로 화면에 MOCK을 표시합니다.

객체 저장소는 전환 뒤에도 FINALIZE 전까지 원본 버킷을 읽기 보조로 사용하므로 route를 MIXED로 보고합니다. 이때 대상만 사용 중으로 표시하고 원본은 읽기 보조로 표시합니다.

## 모니터링과 연결

상단 버튼과 구성도 노드에서 현재 workflow·리소스·환경을 지정해 모니터링으로 이동합니다. 복제 상세 링크는 기존 상세 API의 관측 탭을 열고, 단계 이벤트 링크는 실제 이벤트 시각의 트레이스를 엽니다. 승인·명령 실행은 마이그레이션에 남으며 단계·명령 이력은 접어서 표시합니다. 출발 위치와 이력 페이지를 보존하는 복귀 계약은 `docs/monitoring.md`를 따릅니다.
